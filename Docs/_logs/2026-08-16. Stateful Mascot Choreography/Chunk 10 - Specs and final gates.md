# Chunk 10 — Specs and final gates

## Task

Bring the specs level with the code, then run the expensive gates once against the
finished tree.

This repo's first rule is that specs lead the code (`CLAUDE.md` → "Specs come first"):
a behaviour change that is not in a spec is not finished. Nine chunks have changed
behaviour substantially; the specs still describe the old machine.

## Deliverable

### 1. `Docs/Specs/Menu Bar App.md`

Revise, keeping its existing voice and structure. Specs **name the file that implements a
thing rather than restating its logic** — doc comments carry local detail. Keep it lean;
delete what the code now says better.

Cover:

- The new data flow: `HookServer → SessionTracker → Choreographer → PanelController →
  PanelAdapter → BLEClient`. Update the architecture diagram.
- **Multi-session**: per-session state, the reduction `waiting > working > thinking >
  done > idle`, `done` decaying, staleness reaping, subagent count as intensity. Say
  plainly that this fixes one session's `Stop` cancelling another's `thinking`.
- **Boundary scheduling**: swaps land only on a loop boundary; non-looping clips hand off
  at `motion`, not `duration`; power transitions bypass gating; the target is held, never
  queued, so bursts collapse to one swap.
- **The pose graph**: nodes, loop clips at nodes, transitions as edges, one edge at a time
  recomputed at every boundary, graceful degradation to a direct swap when no path exists.
- **Variants and fidgets**: weighted selection derived from a time epoch (so it is a pure
  function and cannot thrash), no immediate repeat, fidgets on long holds, `<group>-enter`
  one-shots.
- **Event logging**: two JSONL streams under Application Support, always on, capped and
  rotated, tool names only and never `tool_input`.
- Update the file table at the bottom with the new files: `SessionTracker.swift`,
  `Choreographer.swift`, `Clip.swift`, `Pose.swift`, `ClipManifest.swift`,
  `EventLog.swift`.
- Fold in the **measured facts** from `Task.md` that belong in a spec: uploads cost 1–16
  serialized `.withResponse` BLE writes (~60–320ms), panel swaps are visually seamless,
  and **only a new BLE connection flashes the panel's own icon — so connection stability
  is a design constraint**. That last one is a hard-won fact; state it as such.

### 2. `Docs/Specs/Art Pipeline.md`

- `clips.json`, what each field means, and that it is generated by reading back the
  **encoded** GIFs — PIL merges identical consecutive frames, so the in-memory frame list
  and the saved file disagree. This cost a wrong value once already; record it.
- **The anchor contract**: every loopable clip at a pose begins and ends on that pose's
  pixel-identical anchor frame.
- The clip shapes the choreographer keys off: looping variant (shares `variantGroup`),
  fidget (non-looping, `fromPose == toPose`, id not ending `-enter`), entrance one-shot
  (`<group>-enter`). Note that declaring one wrong fails **silently**.
- Transition clips end on a long dwell frame so a hand-off inside the dwell reads as a
  still mascot.

### 4. Final gates — run these and report the output

```
swift build 2>&1 | tail -20
swift test 2>&1 | tail -20
venv/bin/python art/generate.py
venv/bin/python art/export_golden.py
git status --short
./make-app.sh
```

- `swift build` must be **zero warnings**; `swift test` fully green.
- After the two art scripts, `git status --short` must show **no modified files** — the
  committed art must already be exactly what the generator produces. If anything shows as
  modified, the generator and the committed art have drifted: **report it, do not commit
  over it.**
- `./make-app.sh` must build and sign successfully.
- **Do NOT run the app and do NOT attempt any Bluetooth or panel test.** Per
  `CLAUDE.md` and `Docs/Reference/macOS Bluetooth TCC.md`, BLE can only be exercised by
  launching the built `.app` with a user at the keyboard; it is impossible from a tool
  call. The hardware smoke run is the user's, not yours.
